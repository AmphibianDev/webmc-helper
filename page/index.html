      WebMC is a Minecraft launcher whose interface is a web page, and whose promise is that the computer it runs on is borrowed rather than used: the game, the Java runtime and the helper are all deleted when the session ends.

      Why a page cannot launch anything

      A web page cannot start a program, read a file, or look inside /tmp. There is no API for it: WebAssembly and an in-page JVM are sandboxed, file:// gives an opaque origin that cannot even reach 127.0.0.1, a custom protocol handler and a browser extension both need an installer first, and a page has never been allowed to run a file it downloaded.

      Local Network Access, in current Chromium, makes the boundary explicit. Measured from this launcher on GitHub Pages to the helper on 127.0.0.1: fetch() is refused or prompts for permission, an <iframe> comes back with no child frame at all, and a top-level navigation is allowed with no prompt. That last row is why the hosted page hands the tab to the helper's own page the moment it loads.

      What the helper does, step by step

      1. One staging directory under /tmp: a Python runtime if the machine has none, the helper, and later the game.
      2. A Java runtime, found or fetched. The version's own metadata says which Java it needs, and if this machine has nothing suitable one is fetched into the sandbox and dies with it.
      3. The game, from Mojang. Client, libraries and assets, every file verified against its published SHA-1. On a filtered network these come through a relay, or straight through a proxy you already run.
      4. The loader and your mods. Fabric's profile from Fabric's metadata; your jars from this browser's storage, or fetched from Modrinth for the version you picked.
      5. The real client starts — an ordinary java …KnotClient process with a normal window.
      6. You watch it here, in the log along the bottom.
      7. When it exits the helper collects saves, logs, screenshots and configuration into one zip, this page takes it into browser storage, and the sandbox is deleted.

      Where your world lives

      In this browser, under this page's origin, uploaded nowhere, with no account. Storage belongs to an origin, which is why the hosted page hands the tab over instead of running a session itself: one origin, one world, no surprises.

      Networks that block things

      What is blockedWhat happens
      Mojang is unreachableOn Automatic the relay fetches for you over ordinary HTTPS. It is a Cloudflare Worker, deployed and built into the helper, so nobody runs a command or makes an account.
      Minecraft servers are unreachableThe game's connections ride inside the relay too. Put the server in Join this server and the client joins it automatically.
      A proxy is availableDownloads go straight through it: measured 0.88 MB/s against 0.41 MB/s through the relay, so the proxy wins when it can fetch from Mojang — which the helper checks rather than assumes.
      Programs you did not write are blockedNothing here changes that. AppLocker, WDAC, MDM and parental controls are enforced by the operating system.

      More than one window

      Every PLAY is its own session with its own sandbox, Java process and log. Two windows can run at once, including two versions, and stopping one does not touch the other.

      Mod loaders

      Fabric works for any version Fabric supports. Forge and NeoForge do not yet: their installer patches Mojang's jar and their bootstrap refuses to start without that step, so asking for one is refused with that explanation rather than half-launched.

      When something goes wrong

      Read the log; it holds the client's own output, so a crash is readable instead of mysterious. Copy diagnostics in Settings puts everything worth pasting on your clipboard, and the session zip holds the client log and any crash report.

      The promise in one sentence: the game runs on your computer, from a directory under /tmp that is deleted when it ends, while your world and your mods live in your browser — so the machine is borrowed for an hour rather than changed.

      How this works

      Minecraft never becomes a web app here. A helper on this machine downloads the real client and the Java runtime into one directory under /tmp, starts it with Fabric, and when the session ends it hands the saves to your browser and deletes the directory.

      This page cannot start a program, read a file, or see /tmp — the helper does that part. Documentation above has the long version.
