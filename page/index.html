      Documentation

      WebMC is a Minecraft launcher whose interface is a web page, and whose promise is that the computer it runs on is borrowed rather than used: the game, the Java runtime and the helper itself are all deleted when the session ends.

      Why the page cannot launch anything

      This is the first thing to understand, because everything else follows from it. A web page cannot start a program, read a file, or look inside /tmp. There is no API for it, and no amount of cleverness in JavaScript changes that: WebAssembly and an in-page JVM are sandboxed, file:// gives an opaque origin that cannot even reach 127.0.0.1, a custom protocol handler and a browser extension both need an installer first, and a page has never been allowed to run a file it downloaded.

      This is not an accident or an oversight. The features that once did allow it — ActiveX controls, Java applets, Netscape plugins, Flash — were all removed precisely because a web page being able to run native code is a security hole rather than a feature. Every browser still has this rule, on every platform.

      Local Network Access, in current Chromium, makes the boundary explicit. Measured from a public page (this launcher on GitHub Pages) to the helper on 127.0.0.1:

      RouteResult
      fetch()Refused. Chromium asks for permission, or refuses outright: “Permission was denied for this request to access the loopback address space.”
      an <iframe>Refused. The frame tree comes back with no child frame at all — and a blocked iframe still fires load, so the event is not evidence of anything.
      a top-level navigationAllowed, with no prompt and no console error.

      That last row is why this launcher works the way it does. A hosted copy of this page cannot drive the helper directly, so when you press PLAY it hands the tab over to the helper's own page, which is allowed to talk to it: same origin, no permission, no prompt. One click on the GitHub page, and the game starts here.

      What the helper does, step by step

      The helper is a small program you run once. It listens on 127.0.0.1:7645, which is an address only this computer can reach, and it is the only part of this project that ever touches your machine.

      1. It makes one staging directory. Everything it needs goes there and nowhere else: a Python runtime if your machine has none, the helper itself, and later the game. On macOS that is under /tmp; on Windows under %TEMP%.
      2. It finds a Java runtime, or fetches one. You do not need Java installed: if none is found, a JRE is downloaded into the staging directory. A JRE that arrives this way exists only for this session.
      3. It asks Mojang what exists, then downloads the client, the version's own libraries, and the assets — every download verified against the SHA-1 that Mojang publishes, in parallel, into the sandbox.
      4. It installs the mod loader. For Fabric it reads the loader's profile from Fabric's own metadata; for a version with a JAR mod loader the loader's libraries are placed on the classpath. Your mod jars — the ones you dropped on the Mods page, or asked for from Modrinth — are put in the sandbox's mods folder.
      5. It starts the real client. This is an ordinary Java process: the same java -Xmx2G …net.fabricmc.loader.impl.launch.knot.KnotClient any launcher would run. It opens a normal window and plays like any other Minecraft.
      6. You watch it from here. The log panel on the right is the client's own output, streamed as it happens, which is why a crash is readable instead of mysterious.
      7. When the game exits — closed, crashed, or stopped from this page — the helper collects saves, logs, screenshots, configuration, crash reports and its own account of the session into one zip.
      8. The page takes that zip into your browser's own storage, and then tells the helper to delete the sandbox. The helper confirms it is gone.
      9. Nothing has to be cleaned up by you. If the page never comes back — you closed the tab, the browser crashed — the helper deletes the sandbox itself after a deadline. If the helper is killed outright, the next one to start finds the leftover sandbox by its owner file and removes it. If the machine reboots, the operating system clears its own temporary directory.

      What is left afterwards

      There are three levels, and you choose which one you are in:

      How you start itWhat remains when the session ends
      Transient — the macOS Shortcut, or WEBMC_TRANSIENT=1 Nothing at all. The staging directory goes as well: the Python runtime, the helper, the Java runtime, the game, the sandbox.
      Installed — the double-click file, or --install Two small files: one Python file in Application Support, one launch agent so it starts at every login. The game is still deleted every time. --uninstall removes both.
      Browser storage Your world, your mods and your settings, in this origin's own storage. That is the one thing which persists on purpose: it is what makes the game disposable.

      webmc_helper.py --audit prints exactly what the helper has on the machine and nothing else — it claims only what it made, and reports anything merely sharing its name prefix as a count it does not touch.

      Where your world lives

      In this browser, under this page's origin, using the browser's own storage (OPFS where it exists, IndexedDB otherwise). It is never uploaded anywhere, and there is no account. Two consequences worth knowing:

      • Storage belongs to an origin. The hosted page (amphibiandev.github.io) and the helper's own page (127.0.0.1:7645) are different origins, so each has its own worlds. If you play through the hand-over, your world lives with the local page; if you allowed local network access and play inside the hosted page, it lives there.
      • Clearing site data removes it. The session receipt has a “forget everything” link for the same reason.

      Networks that block things

      School and workplace networks block different things, and the launcher answers each separately:

      What is blockedWhat to do
      A proxy is required for all outbound traffic The helper detects a SOCKS5 proxy on 127.0.0.1 (1080, 1088, 10808, 7890) and uses it, resolving names at the proxy. Or pass --proxy socks5h://host:port.
      Mojang is unreachable (blocked, or DNS poisoned to 0.0.0.0) Deploy the relay in relay/relay.js to Cloudflare and paste its URL in Settings: every download then goes through it, over ordinary HTTPS, and is cached at the edge. This is the difference between a launch that works on a locked network and one that does not.
      A browser refuses localhost Use the helper's own page, or allow Local Network Access once for the hosted page. Where an administrator blocked it with LocalNetworkAccessBlockedForUrls, only the helper's own page will do — which is why PLAY hands the tab over.
      Minecraft servers are unreachable (only 443 gets out) Checked in the console: the server address field tunnels a Minecraft server through the relay's WebSocket bridge, so the game connects to a local address and the bytes travel inside an ordinary HTTPS connection.

      More than one window

      Every PLAY is its own session, with its own sandbox, its own Java process and its own log. Two windows can run at once — including two different versions — and stopping one does not touch the other. The Sessions card lists them; click one to read its log. Each finished session keeps its own zip, and each deletes its own sandbox.

      Mod loaders

      LoaderState
      FabricWorks, for any version Fabric supports: mods are loaded at play time by a real JVM, from jars you dropped here or from Modrinth.
      Forge, NeoForgeNot supported yet. Their builds resolve and their libraries download, but neither ships a usable client jar: their installer runs a patching step over Mojang's jar, and their bootstrap refuses to start without it. Asking for one is refused with that explanation rather than half-launched.

      When something goes wrong

      SymptomCause and answer
      Nothing happens when you press PLAY No helper is running. The Sessions card offers the Shortcut, the download, or the link to the helper's own page.
      “no helper” although it is running This browser blocked the request; use the helper's own page, or allow Local Network Access for this site.
      A launch fails with Failed to connect to Mojang The network blocks it, or a proxy that was up has gone. Set a relay, or restart the proxy.
      The game starts without textures or sound Assets were skipped (--no-assets) or failed to download; the log says which.
      A crash Read the log panel, or take the session zip: it contains the client's own log and any crash report. Copy diagnostics in Settings puts everything worth pasting into a bug report on your clipboard.

      How this works

      Minecraft never becomes a web app here. A helper on this machine downloads the real client and the Java runtime into one directory under /tmp, starts it with Fabric, and when the session ends it hands the saves to your browser and deletes the directory.

      The page you are reading cannot start a program, read a file, or see /tmp — the helper does that part. See Documentation in the left rail for the long version.
